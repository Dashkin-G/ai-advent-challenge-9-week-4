# CRM по MCP: сервер и агент в одном приложении

Учебный проект: **собственный MCP-сервер** и **агент**, который подключается к
нему как обычный MCP-клиент. Оба живут в одном процессе FastAPI и поднимаются
одной командой на одном порту.

Экран поделён пополам:

| слева | справа |
|---|---|
| чат с агентом: кнопка подключения к MCP, состояние соединения, список полученных инструментов, журнал обмена | сам MCP-сервер в виде CRM: выключатель сервера, галочки инструментов, данные клиентов и кнопки оператора |

Смысл разделения простой: справа человек меняет данные и настройки сервера,
слева агент видит изменения — через протокол, а не через общую память.

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env      # вписать DASHSCOPE_API_KEY
python -m app.main
```

Открыть <http://127.0.0.1:8000>.

Запускается одна команда, но сервисов два:

* `http://127.0.0.1:8000/` — интерфейс и HTTP-API чата;
* `http://127.0.0.1:8000/mcp/` — MCP-сервер, транспорт streamable HTTP.

## Что попробовать

1. Нажать **«Подключиться»** — агент устанавливает MCP-соединение и получает
   список инструментов; в журнале появляются `initialize` и `tools/list`.
2. Спросить «какие клиенты у нас в работе?» — агент вызовет `list_clients`.
3. Справа сменить статус или завести клиента — и переспросить агента: ответ
   изменится, потому что данные он берёт из сервера, а не из памяти разговора.
4. Снять галочку с `set_status` — инструмент сразу пропадёт и в левом списке.
   Попросить агента сменить статус: он скажет, что такого инструмента нет.
5. Выключить сервер тумблером — соединение закрывается, попытка подключиться
   заново возвращает отказ сервера словами.

## Как устроено

```
app/
  config.py      ключ, модель, порт, адрес MCP
  mcp_server.py  MCP-сервер CRM: данные, пять инструментов, выключатели
  agent.py       MCP-клиент (живая сессия) и вызов модели с инструментами
  main.py        FastAPI: монтирует MCP на /mcp, отдаёт интерфейс и API
static/
  index.html     весь интерфейс: две колонки, приглушённая светлая тема
```

Инструменты сервера: `list_clients`, `get_client`, `create_client`,
`set_status`, `stats`.

Данные CRM и переписка живут в памяти процесса — перезапуск возвращает их в
исходное состояние, и это удобно для показа.

### Минимальный MCP-клиент

Всё подключение к серверу — это несколько строк официального SDK; в проекте они
завёрнуты в класс `McpLink`, который держит сессию открытой:

```python
from mcp import Client

async with Client("http://127.0.0.1:8000/mcp/") as client:
    print(client.server_info, client.protocol_version)
    result = await client.list_tools()
    for tool in result.tools:
        print(tool.name, "—", tool.description)
```

### Почему агент ходит в сервер по сети

Обе половины проекта в одном процессе, и агент мог бы звать функции CRM
напрямую. Он этого не делает: список инструментов, их схемы и результаты
вызовов приходят по MCP. Поэтому в журнале видно настоящий протокол, а сервер
можно выключить или урезать — и агент честно это почувствует.

Python 3.12, ключ Model Studio (DashScope) в `.env`. Модель по умолчанию —
