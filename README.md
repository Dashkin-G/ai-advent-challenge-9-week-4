# GitHub по MCP: свой сервер вокруг чужого API и агент рядом

Учебный проект: **собственный MCP-сервер, обёрнутый вокруг настоящего API** —
GitHub REST — и **агент**, который подключается к нему как обычный MCP-клиент.
Оба живут в одном процессе FastAPI и поднимаются одной командой на одном порту.

Сервер ничего не выдумывает и ничего не хранит: каждый вызов инструмента — это
живой запрос к `api.github.com` по репозиторию этого же курса.

Экран поделён пополам:

| слева | справа |
|---|---|
| чат с агентом: кнопка подключения к MCP, состояние соединения, список полученных инструментов, журнал обмена | сам MCP-сервер: выключатель, галочки инструментов с их входными параметрами и репозиторий глазами человека |

Смысл разделения простой: справа человек смотрит на репозиторий в привычном
виде, слева агент видит то же самое — но через протокол, а не через общую
память.

## Запуск

```bash
pip install -r requirements.txt
cp .env.example .env      # вписать DASHSCOPE_API_KEY
python -m app.main
```

Открыть <http://127.0.0.1:8000>.

Запускается одна команда, но сервисов два:

* `http://127.0.0.1:8000/` — интерфейс и HTTP-API чата;
* `http://127.0.0.1:8000/mcp/` — MCP-сервер, транспорт streamable HTTP.

## Инструменты сервера

Шесть инструментов поверх GitHub REST. Необязательные параметры помечены `?`:
у каждого есть разумное значение по умолчанию, поэтому агент может звать
инструмент и вовсе без аргументов.

| инструмент | параметры | что возвращает |
|---|---|---|
| `repo_info` | `repo?` | карточка репозитория: описание, язык, ветка, звёзды, время последней записи |
| `list_commits` | `limit?`, `branch?`, `path?`, `repo?` | последние коммиты: короткий хеш, автор, дата, первая строка сообщения |
| `commit_details` | `sha`, `repo?` | один коммит целиком: файлы, счётчики строк, куски диффа |
| `list_issues` | `state?`, `limit?`, `repo?` | задачи и pull request'ы с номером, заголовком, автором |
| `list_files` | `path?`, `ref?`, `repo?` | содержимое папки репозитория |
| `read_file` | `path`, `ref?`, `repo?` | текст файла (большие обрезаются, двоичные не читаются) |

Параметр `repo` есть везде: по умолчанию берётся репозиторий из настроек, но
агента можно попросить посмотреть и в чужой — например
`modelcontextprotocol/python-sdk`.

Описания параметров живут прямо в аннотациях функции, а SDK собирает из них
JSON-схему — ту самую, которую агент получает в ответе `tools/list` и передаёт
модели:

```python
async def tool_list_commits(
    limit: Annotated[int, Field(
        ge=1, le=30,
        description="Сколько последних коммитов вернуть, от 1 до 30.")] = 5,
    ...
) -> dict[str, Any]:
```

Схема работает в обе стороны: если модель попросит `limit=99`, вызов не
случится — сервер ответит ошибкой валидации, и модель исправится сама.

## Что попробовать

1. Нажать **«Подключиться»** — агент устанавливает MCP-соединение и получает
   список инструментов; в журнале появляются `initialize` и `tools/list`.
2. Спросить «что изменилось в последнем коммите?» — агент сходит дважды:
   сначала `list_commits`, потом `commit_details` с полученным хешем.
3. Спросить «из каких файлов состоит папка app?» — `list_files`, а следом
   `read_file`, если попросить заглянуть внутрь.
4. Сделать коммит и запушить его — нажать **«Обновить»** в правой панели:
   новая строка подсветится. Переспросить агента — он увидит тот же коммит.
5. Снять галочку с `commit_details` — инструмент сразу пропадёт и в левом
   списке. Попросить подробности коммита: агент скажет, что такого
   инструмента нет.
6. Выключить сервер тумблером — соединение закрывается, попытка подключиться
   заново возвращает отказ сервера словами.

## Как устроено

```
app/
  config.py      ключ модели, репозиторий, порт, адрес MCP
  github_api.py  клиент GitHub REST: запросы и сжатие ответа
  mcp_server.py  MCP-сервер: регистрация инструментов, их схемы, выключатели
  agent.py       MCP-клиент (живая сессия) и вызов модели с инструментами
  main.py        FastAPI: монтирует MCP на /mcp, отдаёт интерфейс и API
static/
  index.html     весь интерфейс: две колонки, приглушённая светлая тема
```

Правая панель ходит в GitHub только при старте и по кнопке «Обновить» —
иначе интерфейс, опрашивающий состояние раз в секунду, сам выел бы весь лимит
запросов.

### Откуда берётся токен

Токен ищется по очереди в трёх местах, и первое же найденное выигрывает:

1. `GITHUB_TOKEN` в `.env` — обычный путь;
2. `gh auth token` — если на машине стоит GitHub CLI и в нём выполнен вход;
3. никакого — публичный репозиторий читается и анонимно, только лимит падает
   с 5000 до 60 запросов в час.

Как именно сервер ходит в GitHub и сколько запросов осталось — написано в
правой панели под выключателем.

### Минимальный MCP-клиент

Всё подключение к серверу — это несколько строк официального SDK; в проекте они
завёрнуты в класс `McpLink`, который держит сессию открытой:

```python
from mcp import Client

async with Client("http://127.0.0.1:8000/mcp/") as client:
    print(client.server_info, client.protocol_version)
    result = await client.call_tool("list_commits", {"limit": 3})
    print(result.structured_content)
```

### Почему агент ходит в сервер по сети

Обе половины проекта в одном процессе, и агент мог бы звать функции
`github_api.py` напрямую. Он этого не делает: список инструментов, их схемы и
результаты вызовов приходят по MCP. Поэтому в журнале видно настоящий
протокол, а сервер можно выключить или урезать — и агент честно это
почувствует.

## Требования

Python 3.12, ключ Model Studio (DashScope) в `.env`. Модель по умолчанию —
`qwen3.8-2.4t-a95b`, меняется переменной `MODEL`. Репозиторий под сервером —
переменной `GITHUB_REPO`.
